# Taskdesk implementation notes

This submission implements the required core and Extension B; invoices (Extension A) are not included. Sessions use opaque random bearer tokens stored as SHA-256 hashes, expire after 12 hours, and are revoked at logout. Passwords use Argon2id. Email addresses are trimmed/lowercased and globally unique. Employees see clients with at least one task assigned to them. New tasks default to the acting admin when no assignee is provided. Login attempts are limited to 8 per IP per 15 minutes. Passwords are required to be at least eight characters because the brief does not specify a minimum. Due dates and task creation times use epoch milliseconds; fees are stored as NUMERIC(12,2).

Branches are one level below a head office. Head-office membership grants access to its branches using the head-office role; a branch membership does not grant access to its parent. A direct branch membership does not override the inherited head-office role. Invite tokens are stored only as hashes and remain usable until accepted because the brief specifies no expiry; no email is sent, so the admin shares the returned invite link. When an account already exists, accepting an invite requires its current password. Core data requests must select an organization when multiple accessible firms exist; the web app stores that selection in an HttpOnly cookie and attaches it to API calls.

The web app is a same-origin Next.js backend-for-frontend that stores the API token in an HttpOnly cookie; browser code never calls the API origin. Date-only form values are interpreted at local midnight before conversion to epoch milliseconds. `.env.example` uses local placeholders and must be updated for the actual PostgreSQL host, database, and accounts. There is no seed data. Tests use a real PostgreSQL database and create/clean up their own firm fixtures. Role checks and firm scoping are enforced by the API even when the interface hides actions.
